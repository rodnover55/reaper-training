# Proposal

## Why

Сейчас со страницы Releases скачивается голый файл модуля. Пользователь сам
ищет папку ресурсов REAPER, создаёт в ней `UserPlugins`, кладёт туда файл, а
на macOS ещё и снимает пометку карантина командой в Терминале. Ошибка на любом
шаге видна только так: расширение не загрузилось, и причины не видно.

## What Changes

- В релизе появляется установщик для каждой системы:
  `reaper-training-<версия>-windows-x64-setup.exe`,
  `reaper-training-<версия>-macos.pkg`,
  `reaper-training-<версия>-linux-x86_64.run`.
- Установщик не просит прав администратора (на Linux — root): всё ставится в
  папку пользователя. Запуск от root на Linux установщик отклоняет: он
  поставил бы расширение не тому пользователю.
- Установщик сам находит REAPER. Если REAPER нет, его версия старше 7 или он
  не той разрядности, установщик объясняет это и ничего не ставит.
- Установщик сам определяет папку ресурсов найденного REAPER — обычную или
  портативную, когда `reaper.ini` лежит рядом с программой, — и кладёт модуль
  в её `UserPlugins`, создавая папку, если её нет.
- Тот же установщик обновляет расширение: заменяет файл прошлой версии.
  Запущенный REAPER установщик просит закрыть (Windows, macOS) или заменяет
  файл так, что запущенный REAPER не падает, и просит его перезапустить
  (Linux).
- На macOS больше не нужна команда `xattr`: файл, поставленный пакетом, не
  получает пометку карантина. Сам пакет не подписан Apple, поэтому при первом
  открытии macOS требует подтверждения — это описано в руководстве.
- Удаление: на Windows — в «Установке и удалении программ», на Linux — тот же
  установщик с ключом `--uninstall`, на macOS — удаление файла, как сейчас
  (у пакетов macOS удаления нет).
- Портативный REAPER, которого установщик не нашёл: на Windows установщик
  предлагает указать его папку, на Linux её передают ключом
  `--resource-path`, на macOS — ручная установка, как сейчас.
- CI собирает установщики вместе с модулями и проверяет их на чистых машинах
  с настоящим REAPER: установка, отказ без REAPER, обновление, удаление.
- Голые файлы модуля остаются в релизе — для ручной установки.
- `docs/install.md` описывает установку установщиком; ручная установка
  остаётся запасным путём.

Вне scope:

- подпись установщиков (Authenticode на Windows, Developer ID и нотаризация на
  macOS): нужны платные сертификаты;
- репозиторий ReaPack;
- пакеты deb и rpm: они ставятся только от root и не пишут в домашнюю папку,
  где REAPER ищет расширения;
- установка на macOS в портативный REAPER.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `platform-support`: расширение ставится установщиком без прав
  администратора; установщик находит REAPER и его папку ресурсов, отказывает
  без REAPER 7 нужной разрядности, обновляет и удаляет расширение; ручная
  установка файлом остаётся; CI собирает и проверяет установщики для Linux,
  Windows и macOS и выкладывает их в релиз.

## Impact

- **`installer/`** — новые исходники установщиков: сценарий Inno Setup для
  Windows, описание пакета (distribution) с проверкой REAPER для macOS,
  сценарий установки на POSIX sh для Linux.
- **`CMakeLists.txt`, `CMakePresets.json`** — цель `installer` и пресет
  сборки, которые собирают установщик для текущей системы.
- **`.github/workflows/build.yml`** — сборка установщиков, их проверка на
  чистых машинах с REAPER, выкладка в релиз вместе с контрольными суммами.
- **Инструменты сборки**: Inno Setup 6 на Windows (бесплатен для
  некоммерческого использования; в раннере `windows-2025` уже стоит),
  `pkgbuild` и `productbuild` из Xcode Command Line Tools на macOS, makeself
  на Linux.
- **Документация**: `docs/install.md`, `README.md`,
  `.github/release-notes.md`.
- **Код модуля не меняется.**
