# Результаты разведки

Разведка шла 2026-10-09, до пропозала: REAPER 7.80 для Linux x86_64, ALSA
`hw:PCH` (встроенная звуковая карта ноутбука), 48 кГц, блок 512, три буфера.
Кабельной петли на стенде нет, поэтому петля акустическая: динамик ноутбука —
встроенный микрофон. MIDI — виртуальное устройство ALSA `hw:VirMIDI`. REAPER
запускался `tools/live/live.py` на Xvfb с отдельной папкой ресурсов
`build/live`. Пробное расширение, скрипты, записи и журналы — вне репозитория,
в `~/Documents/reaper-training-latency-calibration/probes/`
(`latprobe.cpp` — расширение, `analyze.py`, `shift.py` — разбор записей).
Числа стенда — примеры: выводы общие для любой звуковой карты.

## R1. Щелчок из аудиохука в выход и задержка в оба конца

**Метод.** Пробное расширение регистрирует аудиохук и ведёт свой счёт
сэмплов — сумму длин блоков. По команде хук в вызове после обработки
(`isPost`) прибавляет к `GetBuffer(true, канал)` каналов 1–2 щелчок —
64 сэмпла синуса 3 кГц в окне Ханна — и записывает следующие 24 000 сэмплов
входов 1–2. Приход щелчка — пик огибающей корреляции записи со щелчком.
16 щелчков при транспорте, который стоит, на блоках 256, 512 и 1024.

| Блок | `GetInputOutputLatency` вход + выход | Петля по счёту хука | Петля − REAPER |
|---|---|---|---|
| 256 | 256 + 512 = 768 | 679–682 | −88 |
| 512 | 512 + 1024 = 1536 | 1175–1179 | −358 |
| 1024 | 1024 + 2048 = 3072 | 2207–2212 | −864 |

- Хук вызывается и при остановленном транспорте; сигнал, прибавленный к
  выходному буферу после обработки, уходит в выход карты.
- Счёт сэмплов хука — общие часы выхода и входа: задержка в оба конца по нему
  устойчива, ±2 сэмпла на 16 щелчках.
- Настоящая петля на стенде — два блока плюс около 160 сэмплов
  (преобразователи и воздух), а REAPER сообщает три блока. REAPER и тренажёр
  ставят звук раньше: на 7 мс при блоке 512. Поправка поэтому бывает и
  отрицательной.
- Шум комнаты портит часть замеров акустической петли: щелчок теряется под
  громким звуком. Медиана по многим щелчкам их отбрасывает.

## R2. Клики метронома в тренажёре

**Метод.** Метроном REAPER, 120 BPM, звучит из динамика; тренажёр (сборка
ветки `feature/remove-poll-timer`, коммит 1b4694d) меряет вход 1 при записи,
дорожка пишет тот же вход. Ручные поправки REAPER — 0.

- Поиск атак тренажёра находит клики метронома, пришедшие по петле: ноты
  на 0.493068, 1.493074, 1.993041, 2.493077, 2.993091, 3.493071 и 3.993043 с —
  отклонение от доли −6.93 мс, разброс ±0.03 мс. Корреляция пробы (R1) даёт
  −7.04 мс: способы ищут начало щелчка по-разному, разница 0.1 мс.
- Между кликами тренажёр находил и атаки шума комнаты: замер берёт ноты у
  долей метронома.
- Медиана отклонений кликов и есть поправка: тренажёр ставит ноты по правилу
  записи REAPER (`hit-timing`).

## R3. Выход метронома

- Переменной настроек для выхода метронома проекта нет: он есть только
  строкой `METRONOMEOUT` в файле проекта. Для новых проектов —
  `metronome_defout` (на стенде −1). Выходы мастер-дорожки читаются
  `GetTrackNumSends(master, 1)` и `GetTrackSendInfo_Value`.
- Слушать сами клики метронома (R2) значит слышать тот выход, через который
  метроном идёт, без чтения маршрута. Метроном звучит только при
  воспроизведении или записи.
- Первый клик после запуска выходит на один блок позже своей доли (архив
  `add-timing-trainer`, findings R3).

## R4. Время ноты MIDI и счёт сэмплов хука

**Метод.** Таймер главного потока пробы на каждом тике читает
`MIDI_GetRecentInputEvent(0, …)` и счёт хука — номер первого сэмпла
следующего блока. Ноты — виртуальная клавиатура REAPER
(`StuffMIDIMessage(0, …)`) и вход `hw:VirMIDI`: порт секвенсора `20:0`
подписан сам на себя (`aconnect 20:0 20:0`), байты пишутся в
`/dev/snd/midiC1D0`, вход включён `midiins=2` в `build/live/reaper.ini`.

- «Счёт хука + `tsOut`» одинаков до сэмпла при каждом опросе одного события —
  12 опросов подряд, при остановленном транспорте и при воспроизведении.
  Место события в счёте хука — счёт на начало следующего блока плюс `tsOut`.
- У входа `hw:VirMIDI` отметка точнее блока: ноты, посланные через
  1200.25 мс, разошлись по отметкам на 1200.6 мс. События виртуальной
  клавиатуры выровнены по блокам.
- При воспроизведении `projPos` события — ровно позиция его сэмпла в счёте
  хука: «`projPos` − место/48000» постоянно до микросекунды на восьми нотах.
  Правило записи MIDI REAPER (архив `add-midi-input`, findings R2: нота =
  позиция − (блок + выход) / частота) переносится на счёт хука и при
  остановленном транспорте.

## R5. Ручные поправки через `set_config_var_string`

- `set_config_var_string("adjrecmanlatin", "-333", 1)` возвращает 1
  (глобальная настройка). `GetInputOutputLatency` сразу отдаёт вход 179
  вместо 512; строка `adjrecmanlatin=-333` сразу появляется в `reaper.ini`;
  строка состояния тренажёра на следующем тике — «latency 25.1 ms».
- Запись MIDI следует новой поправке без переоткрытия звуковой карты: «нота в
  айтеме − `projPos`» −32.0 мс при `adjrecmanlat` 0 и −42.0 мс после
  `set_config_var_string("adjrecmanlat", "480", 1)`, по четыре ноты.
- Запись звука следует тоже: клики метронома в дубле с `adjrecmanlatin` −333
  позже, чем в дубле с 0, ровно на 333 сэмпла (корреляция окон вокруг долей).
- Отрицательные ручные поправки REAPER принимает.

## R6. Настоящая задержка меняется на ходу

- Во втором дубле R5 после третьего клика клики сдвинулись ещё на
  127 сэмплов (2.6 мс): настоящая задержка карты сменилась посреди записи,
  вероятно после срыва звука. REAPER этого не видит.
- Поправка калибровки верна, пока карта работает без срывов и переоткрытий.
  У USB-карт под Linux задержка меняется и при каждом открытии карты (форумы
  Ardour, отчёт разведки).

## Стенд

- Запись по действию 1016 показывает окно «Select files to save or delete»,
  если `promptendrec` не 0; путь записи — `RECORD_PATH` проекта, иначе дубли
  падают в `~/Documents/REAPER Media`.
- «Error opening devices — ALSA: error opening output device» при запуске,
  если звуковую карту держит звук другой программы: Retry после того, как она
  освободилась.
- Пользователь работает на той же машине: шум комнаты и выключенный звук
  портят акустические замеры — их надо повторять и смотреть, пришёл ли
  сигнал.
