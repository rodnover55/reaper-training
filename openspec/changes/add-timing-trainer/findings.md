# Результаты разведки

Разведка шла на этой машине: REAPER 7.80 для Linux x86_64, встроенная звуковая
карта HDA Intel PCH (кодек ALC3271), встроенный микрофон. Гитары и петли с
выхода на вход нет: источник звука — клики метронома REAPER из динамиков,
которые слышит встроенный микрофон. Отладочная сборка расширения, проверки —
скриптами ReaScript через мост MCP.

## Звуковая система REAPER на этой машине

| Режим (`linux_audio_mode` в `reaper.ini`) | Что это | Что вышло |
|---|---|---|
| 3 | PulseAudio | Работает. 44.1 кГц, блок 512. `GetInputOutputLatency` — вход 87 142, выход 7 423 сэмпла (1.98 с и 168 мс) |
| 0 | JACK | Сервера JACK нет, звук не запускается |
| 1 | ALSA | При 44.1 кГц — окно «Error opening devices»: выход `hw:PCH` 44.1 кГц не умеет (`aplay` получает 48 кГц), вход умеет 44.1–192 кГц. При 48 кГц работает: блок 512, задержки драйвера — вход 512, выход 1 024 сэмпла (10.7 и 21.3 мс) |

Дальнейшая разведка — на ALSA, 48 кГц, блок 512.

## R1. Каналы хука

**`input_nch` и `output_nch` хост не заполняет.** В заголовке SDK у
`audio_hook_register_t` сказано, что их ставит хост. В REAPER 7.80 для Linux
оба остаются нулями и до обработки блока, и после, под PulseAudio и под ALSA,
при остановленном транспорте и при поставленной на запись дорожке.
`GetBuffer(false, i)` при этом отдаёт настоящие входные буферы: в них шум
микрофона.

Решение: число входов хуку сообщает главный поток по `GetNumAudioInputs()` на
каждом тике таймера (`AudioInput::setInputChannels`). Звуковой поток новых
вызовов API не получает.

**Имена каналов.** `GetNumAudioInputs()` = 2, `GetInputChannelName(0)` =
«Input 1», `GetInputChannelName(1)` = «Input 2». Пики каналов хука за первые
7 с: −15.0 и −16.3 dBFS — каналы встроенного микрофона различаются.

**Позиция при остановке.** При остановленном транспорте (`GetPlayStateEx` = 0)
`GetPlayPosition2Ex` в хуке всё равно растёт — на 10 с за 10 с. Сэмплы при
остановке не берутся, так что на измерение это не влияет.

**Нумерация каналов.** Проверена сверкой по сэмплам (см. R2): канал хука 1
бит в бит совпадает с айтемом дорожки, которая пишет «Input 1», а с айтемом
«Input 2» не совпадает нигде; канал хука 2 — наоборот. То есть
`GetBuffer(false, i)` — это вход REAPER номер `i + 1`, а имя канала —
`GetInputChannelName(i)`.

## R2. Правило компенсации

**Метод.** Две дорожки пишут «Input 1» и «Input 2», расширение на лету берёт
канал 1 (или 2) и запоминает сырые сэмплы запуска с позициями блоков.
Отладочное действие «сверить с выделенным айтемом» ищет отрезки айтема на 20,
50 и 80 % его длины в сырых сэмплах по наименьшей разнице. Сэмплы те же самые
(разница/сигнал = 0), поэтому место находится до сэмпла, а сдвиг «на лету −
айтем» и есть то, на что REAPER сдвинул запись. Звук — шум встроенного
микрофона: выход карты выключен в системе, клики метронома в комнату не идут.

Сверка по атакам при таком звуке ненадёжна: атаки шума идут чаще сдвига, и
ближайшая атака — чужая. Поэтому атаки сопоставляются со сдвигом из сверки по
сэмплам; остаток пар после этого — 0.0000 мс, без пары остаются единицы атак
(детекторы на лету и в айтеме начали поток в разных местах, и в густом шуме
мёртвое время сначала расходится).

| Буфер | Скорость | `adjreclat` | Поправки вход / выход | `GetInputOutputLatency` вход / выход | Сдвиг «на лету − айтем», сэмплов реального времени | Остаток пар |
|---|---|---|---|---|---|---|
| 512 | 1.0 | 1 | 0 / 0 | 512 / 1024 | 1536 (32 мс) | 0.0000 мс |
| 512 | 1.0 | 1 | 480 / 0 | 992 / 1024 | 2016 | 0.0016 мс |
| 512 | 1.0 | 1 | 0 / 480 | 512 / 1504 | 2016 | 0.0000 мс |
| 512 | 1.0 | 0 | 0 / 0 | 512 / 1024 | 0 | 0.0000 мс |
| 512 | 1.0 | 0 | 480 / 0 | 992 / 1024 | 480 | −0.0220 мс |
| 512 | 1.0 | 2 | 0 / 0 | 512 / 1024 | 1536 | −0.0109 мс |
| 512 | 1.0 | 4 | 0 / 0 | 512 / 1024 | 1536 | 0.0000 мс |
| 512 | 0.8 | 1 | 0 / 0 | 512 / 1024 | 1536 (25.6 мс шкалы) | 0.0000 мс |
| 128 | 1.0 | 1 | 0 / 0 | 128 / 256 | 384 | 0.0000 мс |
| 1024 | 1.0 | 1 | 0 / 0 | 1024 / 2048 | 3072 | 0.0000 мс |

Сдвиг на 20, 50 и 80 % дубля одинаков во всех строках.

**Правило подтверждено:**

```
t = P + (i / sr - компенсация) * r

компенсация = (вход + выход) / sr   — adjreclat ≠ 0; вход и выход — из
                                      GetInputOutputLatency, ручные поправки
                                      уже в них
            = (adjrecmanlatin + adjrecmanlat) / sr — adjreclat = 0
```

- **Ручные поправки** — `adjrecmanlatin` (вход) и `adjrecmanlat` (выход), в
  сэмплах. `GetInputOutputLatency` возвращает их уже прибавленными к
  задержкам драйвера, и при выключенной галке тоже. Других настроек с именем
  `adjrec*` в бинарнике нет; биты `adjreclat` на `GetInputOutputLatency` не
  влияют.
- **Галка «Use audio driver reported latency»** — `adjreclat`. Включена при
  любом ненулевом значении: 1, 2 и 4 дали одно и то же.
- **Скорость.** Задержка — в реальном времени, на шкалу она ложится с
  множителем скорости проекта: при 0.8 сдвиг 1536 сэмплов = 25.6 мс шкалы.
  Айтем при этом получает скорость тейка 1 / 0.8 = 1.25.
- **Чтение айтема.** Время `CreateTakeAudioAccessor` отсчитывается от начала
  айтема и уже пересчитано к скорости тейка: при скорости тейка 1.25 сэмплы
  чтения — не сэмплы файла. Сверка на время чтения ставит тейку скорость 1.
- **Когда REAPER берёт задержку.** На ALSA задержка постоянна весь сеанс, и
  отличить «при старте записи» от «в другой момент» нельзя. Поправка,
  записанная в настройки за миг до Record, уже действует на этот дубль.
  Плагин снимает компенсацию при запуске транспорта (design D2).

Стоп-условие не наступило.

## R3. Удары метронома

**Метод.** В отладочной сборке хук после обработки блока пишет выходной канал 1
REAPER с позицией блока — в нём клики метронома, даже когда выход карты
выключен в системе. Отладочное действие «metronome» находит клики тем же
детектором и для каждого печатает такт и долю по `TimeMap2_timeToBeats`,
отклонение от целой доли (`TimeMap2_beatsToTime`) и рисунок
`TimeMap_GetMetronomePattern`.

Проект: такты 1–2 — 4/4, 120 BPM; 3–4 — 6/8; 5–6 — 7/8 с рисунком
`ABCABCD` (поставлен `TimeMap_GetMetronomePattern(…, "SET:ABCABCD")`, это
добавило свою метку темпа); 7–8 — 4/4 с плавным изменением темпа 100 → 140.
Темп REAPER задаёт в четвертях: такт 6/8 длится 1.5 с, 7/8 — 1.75 с.

| Размер | Кликов на такт | Единиц `TimeMap2_timeToBeats` на такт | Наибольшее отклонение клика от целой доли |
|---|---|---|---|
| 4/4, 120 BPM | 4 | 4 | 0.016 мс |
| 6/8 | 6 (по восьмым) | 6 | 0.016 мс |
| 7/8, рисунок ABCABCD | 7 (по восьмым) | 7 | 0.034 мс |
| 4/4, 100 → 140 плавно | 4 | 4 | 0.040 мс |

- Удар метронома — единица `TimeMap2_timeToBeats`, она идёт по знаменателю
  размера. Рисунок меняет только акцент клика (пики A −12, B −22, C −26,
  D −32 dB), но не число кликов. Design D5 подтверждён.
- Отклонения в сотые доли миллисекунды — точность детектора на форме клика.
- **Первый клик после запуска транспорта** выходит на один блок позже своей
  доли: 10.671 мс при блоке 512 и 48 кГц, и при запуске с 0, и с 10 с.
  Остальные клики точны. Гитарист под первый клик всё равно не играет.

## R4. Позиция блока на краях

Журнал отладочной сборки пишет смену состояния транспорта, позиции первых
блоков после неё и каждый блок, позиция которого не продолжает прошлый.

| Случай | Что делает позиция обработки `P` в хуке | Сэмплы идут | Решение |
|---|---|---|---|
| Запуск воспроизведения или записи | Стоит на позиции запуска 4–5 блоков (около 50 мс), потом растёт | да | Блоки со стоящей позицией не мерятся (скорость по соседним блокам — 0) |
| Count-in перед записью (`projmetroen` бит 16, 1 такт) | Стоит на позиции начала записи весь отсчёт и ещё задержку вывода: 191 блок ≈ 2.04 с; состояние — 5 (запись) | да | **Во время count-in не мерить**: удары отсчёта не лежат на шкале. Получается само из правила стоящей позиции |
| Бит 8 `projmetroen` при записи | Отсчёта нет | — | Это не count-in перед записью; что он включает, не выяснялось |
| Пре-ролл перед записью (действие 41819, `prerollmeas` = 1) | Идёт с начала пре-ролла (7.9947 при записи с 10.0), первые 2 блока стоят | да | Мерить: позиции настоящие |
| Петля 10–12 с повтором | На переходе следующий блок начинается на длину петли раньше (10.0053 после 11.9947): граница петли — внутри блока | да | Время ноты при включённом повторе и позиции внутри петли заворачивается в петлю (design D2) |
| Пауза | Сэмплов нет (состояние 2) | нет | — |
| Продолжение после паузы | Откат назад на задержку вывода (14.6293 → 14.6080, 1024 сэмпла), потом стоит около 4 блоков | да | Новый запуск: список в окне очищается |

Действия для count-in в REAPER нет; есть только для пре-ролла (41818 — при
воспроизведении, 41819 — при записи), и они `projmetroen` не меняют. Число
тактов отсчёта — `projmetrocountin`, пре-ролла — `prerollmeas`; обе —
настройки проекта.

## Проверка окна и измерения вживую (задачи 6.1–6.3, 7.1–7.5)

ALSA, 48 кГц, блок 512. Звук — шум встроенного микрофона, поэтому числа в
строках случайные; проверялись поведение, цвета и отметки.

**Время нот против записи (6.1).** Дорожка пишет «Input 1», тренажёр на лету
меряет тот же вход; отладочная сверка сравнивает ноты с записанным айтемом.
Порог тишины −60 dBFS: в тихой комнате атак шума около одной в секунду.

| Input manual offset | Компенсация тренажёра при запуске | Сдвиг айтема REAPER | Нот в паре | Остаток |
|---|---|---|---|---|
| 0 | 32.000 мс | 32.0000 мс | 25 из 25 | 0.0000 мс |
| 480 сэмплов | 42.000 мс | 42.0000 мс | 27 из 27 | 0.0000 мс |

Поправка сдвигает время нот тренажёра ровно так же, как записанный звук. Ноты
мерились и во время записи.

**Окно и действия (6.2, 6.3, 7.1–7.4).**

| Сценарий | Что видно |
|---|---|
| Открытие окна | Действие показывает окно в нижнем доке REAPER (вкладка «Timing trainer»), повторное — скрывает; переключатель 1 и 0 |
| Режим «шестнадцатые» | Подпись «такт.удар», четыре узла, среднее и разброс; новые строки сверху |
| Цвета, пропуск, лишняя нота | Не больше допуска — зелёное, больше — красное; «.» и «*»; разброс серый |
| Остановка | Строки остаются, состояние «waiting for playback» |
| Новый запуск | Список очищен |
| Режим действием | «Mode: quarters» включает четверти, переключатели «четверти» 1, «шестнадцатые» 0; одно значение в строке, без среднего и разброса |
| Смена допуска на ходу | Допуск 5 мс в поле и в строке состояния, цвета по нему |
| Скорость 0.8 | Строка состояния «rate 0.8 — measuring» |
| Канала нет | Вход 3 при двух входах: поле пустое, «selected input is not available», нот нет |
| Перезапуск REAPER | Режим, допуск, вход и порог сохранились (`reaper-extstate.ini`, раздел `reaper_training`), окно открылось снова в доке |

Место в доке по умолчанию REAPER в `reaper.ini` не пишет: записи нет, пока
окно не перенесли в другой док.

**Задержка показа (7.5).** 240 BPM, шестнадцатые, 30 с воспроизведения, 19
нот. Задержка — от прихода блока атаки в хук до тика таймера, который
перерисовывает окно, плюс задержка ввода (10.7 мс): наименьшая 12.3 мс,
медиана 28.2 мс, 95-й процентиль 48.6 мс, наибольшая 50.2 мс — при пределе
250 мс.

## CI на GitHub (задачи 2.1, 2.2)

Первый прогон после push (`ae22f27`): задачи «Linux x86_64» и «macOS (Apple
Silicon и Intel)» прошли, в артефактах `reaper_training.so` (490 КБ) и
`reaper_training.dylib` (206 КБ). Проверка наименьшей macOS в журнале:
`arm64: minos 12.0`, `x86_64: minos 12.0`.

Что проверка падает при другой версии, проверено локально, а не прогоном CI:
шаг из `.github/workflows/build.yml` запущен с поддельным `vtool`, который
печатает `minos 13.3`, — шаг завершился с ошибкой «наименьшая macOS 13.3, а
нужна 12.0»; с `minos 12.0` — прошёл.

## Count-in и петля в окне (часть задачи 8.1)

**Count-in перед записью** (`projmetroen` 23, 4 такта, запись с 10 с, порог
тишины −70 dBFS). Отсчёт шёл 8 с; за это время рабочий поток нашёл и отбросил
56 атак — у всех позиция блока стояла на 10.000000. Первая измеренная нота —
сразу после отсчёта, t = 10.075.

**Петля 10–12 с с повтором** (шестнадцатые, 120 BPM, около пяти проходов, 42
ноты). Время всех нот легло в окно заворота [9.9375, 11.9375): от 9.9415 до
11.9259. Подписи строк — только 6.1–6.4, то есть такт петли; каждый проход
заводит новые строки тех же ударов.
