# Proposal

## Why

Решения тренажёра написаны в `Trainer` и в окне вперемешку с вызовами API
REAPER, а `Trainer` без REAPER не создаётся. Это решения о том:
- что делать на запуске и остановке транспорта;
- какую ноту MIDI взять, а какую отбросить;
- в каком состоянии тренажёр: ждёт ли запуска, меряет ли, есть ли вход;
- как идёт калибровка и на каком она этапе.

Юнит-тесты до них не достают. Чтобы их проверять, в отладочный модуль
добавили функции ReaScript `TrainingDebug_*` и отладочные действия. Из-за
этого:
- проверки вживую управляют тренажёром изнутри модуля и проверяют его
  логику, а заодно и поведение REAPER;
- тестовый код живёт в модуле расширения — в отладочной сборке, которая
  ставится и в REAPER, на котором играет пользователь.

## What Changes

- Решения тренажёра выносятся в чистый код без REAPER и покрываются
  юнит-тестами: всё, что приходит от REAPER, передаётся параметрами.
- Чистый код держит состояние тренажёра, а окно строит из него само текст
  строки состояния и видимость, доступность и подписи кнопок.
- Модуль расширения становится связкой: читает REAPER, передаёт данные
  чистому коду и исполняет его решения.
- Поведение REAPER не тестируется: его выясняет разведка и записывает фактами
  в `findings.md` изменения.
- Проверка вживую проверяет только связку с REAPER, чёрным ящиком:
  - публичный API REAPER из скриптов;
  - виртуальная MIDI-клавиатура;
  - щелчки и снимки окна на Xvfb;
  - журнал тренажёра.
- Из модуля убирается код только для проверок:
  - функции ReaScript `TrainingDebug_*` и отладочные действия
    (`debug_actions.cpp`);
  - отладочные функции окна;
  - нота без входа (`addTestNote`);
  - звук калибровки из массива;
  - списки нот последнего запуска (`lastRun`, `lastMidiRun`);
  - порог энергии удара для проверок (`setEnergyRatio`).
- Правило проверки задач в `openspec/config.yaml` описывает этот порядок.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: поведение для пользователя не меняется.

## Impact

- `src/trainer.cpp`, `src/trainer.hpp`, `src/window.cpp`, `src/window.hpp`,
  `src/audio_input.hpp` — решения уходят в чистый код, код только для
  проверок удаляется.
- `src/debug_actions.cpp`, `src/debug_actions.hpp` — удаляются.
- `src/main.cpp`, `CMakeLists.txt` — регистрация отладочных действий, макрос
  `TRAINING_DEBUG_BUILD`, новая библиотека чистого кода.
- `libs/onset` — смена порога энергии удара на ходу удаляется.
- `tests/` — юнит-тесты решений тренажёра.
- `tools/` — инструменты проверки вживую на Xvfb.
- `openspec/config.yaml` — правило проверки задач и правило о ссылках в
  комментариях кода.
- `README.md` — описание отладочной сборки.
