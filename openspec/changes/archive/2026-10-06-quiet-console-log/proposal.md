# Proposal

## Why

При каждом запуске REAPER расширение пишет в консоль REAPER строку
«reaper-training … loaded», и REAPER открывает ради неё окно «ReaScript
console output». Пользователю это окно ни к чему. Журнал, по которому можно
разобраться, что случилось, при этом пишется только в отладочной сборке.

## What Changes

- **BREAKING** (для пользователя): при загрузке строки в консоли REAPER
  больше нет. Её включает скрытая настройка `console_log=1` в разделе
  `[reaper_training]` файла `reaper-extstate.ini` — для тестовых сборок. В окне
  тренажёра этой настройки нет, по умолчанию она выключена. Та же настройка
  управляет выводом отладочных действий в консоль.
- Журнал `reaper-training.log` в папке ресурсов REAPER пишется в любой сборке,
  а не только в отладочной. Первая строка запуска — версия и время сборки.
- Чтобы журнал не рос без конца, при запуске файл больше 5 МБ переименовывается
  в `reaper-training.log.1`, прежний `.1` пропадает.
- Установщики и руководство по установке больше не обещают строку в консоли:
  проверить установку можно по действию «reaper-training: Show/hide timing
  trainer» в списке действий или по журналу.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `platform-support`: при загрузке расширение пишет версию и время сборки в
  свой журнал, а в консоль REAPER — только со скрытой настройкой; журнал
  пишется в любой сборке, а при загрузке журнал больше 5 МБ уходит в `.1`.

## Impact

- **`src/`**: `journal` — запись во всех сборках и замена большого файла;
  `main.cpp` — журнал открывается всегда, строка в консоли — по настройке;
  `settings` — чтение скрытой настройки; `debug_actions.cpp` — вывод в консоль
  по настройке.
- **Установщики**: финальные сообщения Windows, macOS и Linux.
- **Документация**: `docs/install.md` — как проверить, что расширение
  загрузилось; `README.md` — скрытая настройка для тестовых сборок;
  описание релиза 0.5.0.
