# Proposal

## Why

У тренажёра два источника правды о транспорте. Главный поток узнаёт о запуске
и остановке из уведомления REAPER `SetPlayState` и передаёт их рабочему потоку
через `AudioInput::startRun` и `stopRun`. Аудиохук выводит то же сам: на каждом
блоке спрашивает `GetPlayStateEx` и вместе с флагом `setCalibrating` решает,
брать ли звук для атак или для калибровки.

На один запуск транспорта в ядре заводятся два запуска: `Transport` начинает
свой сразу по `SetPlayState`, а `OnsetSearch` — позже, когда рабочий поток
заметит сигнал, и без момента начала. При остановке и запуске в одном вызове
звук идёт без перерыва, и блоки старого запуска, ещё лежащие в очереди,
разбирает детектор нового запуска.

Решения о транспорте — дело ядра `libs/trainer`: у связки с REAPER своих
условий о транспорте нет.

## What Changes

- Ядро получает свои часы: тип момента `trainer::Moment` — целые наносекунды.
  Все моменты, которые ядро получает и сравнивает, — в нём.
- `OnsetSearch` — во владении `Transport`: поиск атак начинают и кончают
  только `Transport::start` и `stop` через атомарное состояние запуска; своего
  статуса запуска у поиска нет. Поиск читает это состояние перед каждым
  блоком: забывает детектор при новом моменте начала и выбрасывает блоки,
  взятые раньше начала, до детектора. `followRun`, `startRun` и `stopRun`
  уходят.
- `MidiNotes` — поле `Transport`: отбор нот MIDI начинает `Transport::start`,
  а не `Trainer`.
- Класс `Surface`, который передаёт тренажёру уведомления REAPER, называется
  `ReaperNotificationRelay`, файлы и функции регистрации — по нему.
- Режим звукового пути — ничего, звук для атак или звук для калибровки —
  вычисляет ядро; звуковому пути его передаёт одно атомарное значение.
  `setCalibrating` уходит.
- Аудиохук не зовёт `GetPlayStateEx`: берёт звук выбранного канала по режиму и
  пишет в заголовок блока режим и момент, когда взял блок.
- Номера запуска нет: `OnsetSearch::run_`, `AudioOnset::run` и `run=N` в
  журнале уходят.
- `Transport::takesOnset` по-прежнему отбрасывает атаки, блок которых взят
  раньше начала текущего запуска.
- Журнал: «start:» пишет момент начала запуска, «onset» — момент своего
  блока, оба в формате часов ядра.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: поведение для пользователя не меняется.

## Impact

- `libs/trainer` — часы ядра; `Transport` с поиском атак, отбором нот MIDI и
  состоянием запуска; `OnsetSearch`, `AudioBlock`, `AudioOnset`, `Calibrator` —
  моменты в часах ядра; режим звукового пути; юнит-тесты.
- `src/audio_input.cpp`, `src/audio_input.hpp` — режим вместо флагов, хук без
  `GetPlayStateEx`, рабочий поток, в котором ядро (`trainer::OnsetSearch`)
  ищет атаки, только подаёт блоки в поиск из `Transport`.
- `src/trainer.cpp`, `src/trainer.hpp` — моменты в часах ядра, режим
  звукового пути, порядок полей `Transport` и `AudioInput`, отбор нот MIDI у
  `Transport`, «start:» с моментом начала.
- `src/control_surface.cpp`, `src/control_surface.hpp` →
  `src/reaper_notification_relay.cpp`, `.hpp`; `src/main.cpp` и
  `CMakeLists.txt` — новые имена.
- `src/main.cpp` — без `REAPERAPI_WANT_GetPlayStateEx`.
