# Результаты разведки

Разведка шла 2026-10-07 на REAPER 7.80 для Linux x86_64: ALSA `hw:PCH`, 48 кГц,
блок 512, REAPER на виртуальном дисплее Xvfb. Проверялась и сборка REAPER 7.82
x64 под Wine с пустым аудиоустройством (Dummy Audio).

Инструмент — отдельное пробное расширение, код тренажёра не тронут. Проба
регистрирует:
- невидимую поверхность управления (`csurf_inst`) и пишет в журнал каждый
  вызов `SetPlayState`, `SetRepeatState` и `Extended` со временем
  монотонных часов и потоком;
- аудиохук: на каждом блоке — перемены `GetPlayStateEx`, поля `input_nch` и
  `output_nch` и первый канал, для которого `GetBuffer` вернул пустой
  указатель;
- таймер REAPER: на каждом срабатывании — перемены `GetPlayStateEx`.

Сценарии гонит Lua-скрипт через `reaper -nonewinst`.

## R1. Перемены транспорта: `SetPlayState`

`SetPlayState` приходит в главном потоке, прямо в вызове, который меняет
транспорт. Время — от `SetPlayState` до первого блока хука и до срабатывания
таймера с новым состоянием:

| Перемена | `SetPlayState(play, pause, rec)` | Хук | Таймер |
|---|---|---|---|
| `OnPlayButton` | 1, 0, 0 | +6.8 мс | +9.1 мс |
| `OnPauseButton` (пауза) | 0, 1, 0 | +5.2 мс | +12.0 мс |
| `OnPauseButton` (продолжение) | 1, 0, 0 | +4.9 мс | +9.8 мс |
| `OnStopButton` | 0, 0, 0 | +4.7 мс | +9.0 мс |
| действие 1007 (Play) | 1, 0, 0 | +7.4 мс | +11.3 мс |
| действие 1016 (Stop) | 0, 0, 0 | +9.6 мс | +10.1 мс |
| действие 1013 (Record) | 1, 0, 1 | +7.9 мс | +11.5 мс |
| `OnStopButton` и `OnPlayButton` в одном вызове | 0, 0, 0 и сразу 1, 0, 0 | перемены нет | перемены нет |

Остановку и запуск в одном вызове хук и таймер не видят вовсе: на блоке и на
срабатывании транспорт идёт, как и раньше. `SetPlayState` приходит на обе.

Таймер может опаздывать сильнее: при запуске записи с count-in он увидел
запись через 218 мс после `SetPlayState` — главный поток был занят.

Под Wine — то же: `SetPlayState` в главном потоке, раньше хука и таймера.

## R2. Count-in

Count-in перед записью включают биты 1 (метроном) и 16 (отсчёт) переменной
проекта `projmetroen`, значение 23. `reaper.set_config_var_string` ставит его
из скрипта; третий аргумент обязателен. Бит 2 переменной `preroll` — это
пре-ролл (позиция идёт с отрицательных значений), а не count-in.

При нажатии записи `SetPlayState(1, 0, 1)` приходит сразу. Позиция стоит 4 с
(два такта при 120 ударах в минуту) и потом трогается. На сдвиг позиции
поверхность управления ничего не получает: конец отсчёта видно только по
позиции.

## R3. Скорость и повтор

- Смена скорости (`CSurf_OnPlayRateChange` 1.5 и 1.0) —
  `Extended(CSURF_EXT_SETBPMANDPLAYRATE)` с `bpm` = null и `rate` = 1.5 и 1.0.
- Переключение повтора — `SetRepeatState(1)` и `SetRepeatState(0)`.

Оба — сразу и в главном потоке.

Скорость нового проекта уведомление не передаёт. При открытии проекта, в том
числе при запуске REAPER с проектом, и при переключении вкладок проектов
поверхность получает подряд `SetPlayState(0, 0, 0)`, `SetRepeatState`,
`Extended(CSURF_EXT_SETBPMANDPLAYRATE)` с `bpm` = 120 и `rate` = null,
`SetTrackListChange` и `Extended(CSURF_EXT_RESET)`. `Master_GetPlayRate` в
этот момент уже отдаёт скорость нового проекта. Проба — проекты со скоростью
1.5 и 1.0: открытие в той же вкладке, новая вкладка (действие 40859),
возврат на вкладку (`SelectProjectInstance`), запуск REAPER с файлом проекта.

## R4. Каналы хука: `input_nch` и `GetBuffer`

`input_nch` и `output_nch` всегда 0:
- внутри `OnAudioBuffer`, до обработки блока (`isPost` = false) и после;
- при остановленном транспорте, на воспроизведении и с дорожкой на записи с
  мониторингом входа;
- снаружи хука тоже.

При этом `GetNumAudioInputs` = 2. Под Wine оба поля тоже 0.

`GetBuffer` для канала, которого нет у карты, отдаёт пустой указатель. Входы 0
и 1 дают буфер, со входа 2 и дальше — пусто; с выходами так же. Под Wine у
Dummy Audio входов нет, и пусто уже со входа 0.

Открытый код берёт каналы так же — через `GetBuffer` с проверкой на пустой
указатель, без числа каналов:
- LICEcap (Cockos, `licecap_ui.cpp`) берёт `GetBuffer(true, 0)` и
  `GetBuffer(true, 1)`, а если второго нет, подставляет первый;
- reamo (`audio_hook.zig`) прямо пишет: «Don't iterate output_nch — REAPER may
  not set it in the struct».

## R5. История MIDI-входа

Ноты подавались в виртуальную MIDI-клавиатуру (`StuffMIDIMessage(0, …)`)
порциями по 100 на каждом цикле `defer`, 63 000 всего. После этого в истории
46 568 событий: новейшее — номер 0x40000000 + 63 000, самое старое из
оставшихся — + 16 433. Через 15 с — то же. История держит последние 46 568
коротких (3 байта) событий и вытесняет старые.

Нота виртуальной клавиатуры, поданная в том же вызове, что и запуск
транспорта с позиции 0, пришла в первом блоке после запуска — вместе со
сдвигом позиции — с `pp` = 22.0: позицией часов остановленного транспорта.
Нота через 1 с — с верной `pp` = 0.98. Ноты первого блока после запуска
ненадёжны, как ноты count-in.

До начала проекта `TimeMap2_timeToBeats` отдаёт удар в такте отрицательным
от начала следующего такта: при 120 ударах в минуту и 4/4 время −0.25 с —
такт 0, удар −0.5; −1.0 с — такт 0, удар −2.0; −2.25 с — такт −1, удар −0.5.
Нота MIDI через 20 мс после запуска с позиции 0 при компенсации 32 мс ложится
на время −0.012 с, и такт по такому ответу не содержит её удар.

Чтение по номеру тем медленнее, чем старше событие: 9 286 чтений подряд с
номера 0 заняли 7.4 с. Число событий истории пробе пришлось считать
двоичным поиском. Тренажёр читает только новые события с прошлого чтения.

## R6. Звуковая карта и её закрытие

Про звуковую карту в API четыре функции:
- `Audio_Init` — «open all audio and MIDI devices, if not open»;
- `Audio_Quit` — «close all audio and MIDI devices, if open»;
- `Audio_IsRunning`;
- `Audio_IsPreBuffer`.

Попросить REAPER держать карту открытой или сообщить, что она нужна
расширению, нечем.

Настройка «Close audio device when stopped and application is inactive»
хранится битом 1 переменной `audiocloseinactive` (под Linux —
`audiocloseinactive_linux`).

Расширения в открытом коде (поиск по GitHub: `Audio_Init`, `Audio_IsRunning`)
карту не открывают. reallm только проверяет `Audio_IsRunning`. Инструменты
REAPER (тюнер, мониторинг входа) с настройкой не спорят: пока карта закрыта,
звука у них нет.

## R7. Устройства MIDI в поверхностях управления SDK

Примеры поверхностей управления из SDK (`reaper-plugins/reaper_csurf`: Mackie
Control, BCF2000, FaderPort, TranzPort и другие) устроены одинаково:
1. Устройство выбирают в окне настроек поверхности; список строится через
   `GetMIDIInputName`. В настройках хранится номер устройства REAPER:
   `csurf_mcu.cpp` пишет `m_midi_in_dev` числом.
2. Устройство открывается при создании поверхности (`CreateMIDIInput`). Если
   не открылось, REAPER показывает своё окно «could not be opened».
3. Когда REAPER меняет номера устройств, он вызывает
   `Extended(CSURF_EXT_MIDI_DEVICE_REMAP, isout, старый, новый)`, и
   поверхность заменяет сохранённый номер — макрос `DEFAULT_DEVICE_REMAP` в
   `csurf.h`, его используют 8 примеров.

Сторонние расширения поступают так же: jprsurf (`OnMidiDeviceRemap`), обёртки
rea-rs (Rust) и Reaper-Zig-Project. Опроса устройств и поиска по имени ни в
одном из них нет.
