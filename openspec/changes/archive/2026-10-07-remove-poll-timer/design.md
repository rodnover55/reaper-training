# Design

## Context

Мотивация — `proposal.md`, раздел Why; требования — дельты `input-calibration`
и `timing-display`; разведка — `findings.md` этого изменения.

Сейчас `initTrainer` регистрирует таймер REAPER (`Register("timer", …)`, около
30 раз в секунду). На каждом срабатывании `Trainer::poll`:
- сообщает хуку число входов (`GetNumAudioInputs`);
- сравнивает транспорт с прошлым срабатыванием (`GetPlayStateEx`) и на
  запуске зовёт `start()`, а на остановке каждый раз снимает компенсацию;
- берёт скорость проекта (`Master_GetPlayRate`);
- считает строку состояния: `GetInputChannelName`, маску включённых входов
  MIDI; раз в секунду ищет вход MIDI по имени;
- ведёт калибровку и раз в секунду открывает закрытую звуковую карту;
- сообщает строкам позицию;
- забирает атаки и историю MIDI-входа;
- перерисовывает окно.

Что показала разведка (`findings.md`):
- **`SetPlayState` поверхности управления** приходит в главном потоке, прямо
  в вызове, который меняет транспорт, — на 4–10 мс раньше, чем перемену
  увидит аудиохук, и раньше кадра. Приходит на запуск, паузу, продолжение,
  остановку и запись, из скриптов и действий; на остановку и запуск в одном
  вызове — дважды, хотя опрос на кадре такую перемену не видит. Конец
  count-in не сообщается: позиция стоит, потом трогается.
- **Скорость проекта** приходит как `Extended(CSURF_EXT_SETBPMANDPLAYRATE)`.
- **`input_nch` и `output_nch` хука** всегда 0. `GetBuffer` для канала, которого
  нет у карты, отдаёт пустой указатель. Так же каналы берут LICEcap (Cockos) и
  reamo.
- **История MIDI-входа** держит последние 46 568 коротких событий.
- **API удержания звуковой карты нет**: только `Audio_Init`, `Audio_Quit`,
  `Audio_IsRunning`. Расширения и инструменты REAPER с настройкой закрытия
  карты не спорят.
- **Поверхности управления из SDK** (`reaper_csurf`) хранят номер устройства
  MIDI и меняют его по `CSURF_EXT_MIDI_DEVICE_REMAP` (макрос
  `DEFAULT_DEVICE_REMAP`, `csurf.h`).

## Goals / Non-Goals

**Goals:**
- На кадре — только отрисовка и то, что ей нужно: позиция воспроизведения,
  данные из очередей хука и истории MIDI-входа.
- Ничего, что меняется только со сменой конфигурации, на кадре не проверяется.

**Non-Goals:**
- Компенсация остаётся как есть: при запуске транспорта — для измерения, на
  остановке — на каждом кадре для строки состояния, потому что настройки, от
  которых она зависит, могут меняться.
- Следование за позицией воспроизведения остаётся на кадре.

## Decisions

### D1. Кадр рисует, данные приходят из хуков и событий

Разведка — `findings.md`, R1 и R5.

Таймер главного потока остаётся и только рисует. Время нот от кадра не
зависит: позицию блока даёт аудиохук, позицию ноты MIDI — история MIDI-входа.
Кадр забирает уже готовые данные и рисует.

Отвергнуто: убрать таймер целиком. Отрисовке и следованию за позицией нужен
главный поток, а функции карты темпа (`TimeMap`) обещаны только в нём.

### D2. Транспорт и скорость — уведомления поверхности управления

Разведка — `findings.md`, R1 и R3.

Тренажёр регистрирует невидимую поверхность управления (`csurf_inst`):
- `SetPlayState(play, pause, rec)` запускает `start()` на переходе к
  воспроизведению или записи и `bars_.stop()` на остановке и паузе;
- `Extended(CSURF_EXT_SETBPMANDPLAYRATE)` меняет скорость проекта. При
  открытии проекта и смене вкладки скорости в уведомлении нет, и она берётся
  из `Master_GetPlayRate` (`findings.md`, R3).

`GetPlayStateEx` и `Master_GetPlayRate` на кадре не зовутся; скорость
читается при загрузке и по уведомлению.

Атаки прошлого запуска отделяются по монотонным часам: `start()` запоминает
момент запуска, и атаки из блоков, полученных хуком раньше, в строки не
попадают. Номер запуска хука для этого не годится: при остановке и запуске в
одном вызове звук идёт без перерыва, и номер не меняется.

Почему: уведомление приходит синхронно с переменой, раньше хука и кадра, и не
пропускает остановку с запуском в одном вызове.

Отвергнуто: опрос на кадре — запаздывает до кадра и не видит коротких
перемен.

### D3. Канал звуковой карты — из настроек, отсутствие — по `GetBuffer`

Разведка — `findings.md`, R4.

Хук читает `GetBuffer(false, settings.channel)`. Пустой указатель — канала у
карты нет, сэмплов нет. Хук ставит атомарный признак «канал есть», строка
состояния берёт его. `setInputChannels`, `inputChannels_` и
`GetNumAudioInputs` на кадре убираются. Список Input строится по
`GetNumAudioInputs` при показе настроек.

Отвергнуто: передавать хуку число каналов — `input_nch` не заполняется, а
проверка по пустому указателю уже защищает.

### D4. Калибровка открывает карту один раз

Разведка — `findings.md`, R6.

При запуске калибровки закрытая карта открывается (`Audio_Init`) один раз.
Если REAPER закрыл карту посреди калибровки, звук перестаёт приходить, и через
2 с калибровка обрывается «нет звука». Сообщение называет настройку «Close
audio device when stopped and application is inactive». `openAudioDevice` с
попытками раз в секунду убирается.

Отвергнуто: открывать карту снова — удержать её открытой через API нельзя.

### D5. История MIDI-входа без потерь

Разведка — `findings.md`, R1, R2 и R5.

`start()` не пропускает историю MIDI-входа. Ноты до запуска отбрасываются и
так: история читается на каждом кадре, а у нот при остановке и паузе `pp` =
−1. Count-in отсчитывается от настоящего запуска: позиция начала берётся в
`SetPlayState`, до того как её сдвинул звук. Когда позиция сдвинулась, кадр
считает, как и сейчас (`movedAgo`), по разнице позиций и скорости: позиция
идёт со скоростью проекта, так что разница даёт время от сдвига.

Нота сразу после запуска с начала проекта за вычетом компенсации записи MIDI
ложится до начала проекта. Для такого времени `TimeMap2_timeToBeats` отдаёт
удар в такте отрицательным — от начала следующего такта (`findings.md`, R5);
такт ноты считается с поправкой на это.

Отвергнуто: граница запуска по кадру — теряет ноты до первого кадра.

### D6. Вход MIDI — номер устройства REAPER

Разведка — `findings.md`, R7.

В настройках хранится номер устройства (`midiIndex`), имя (`midiInput`) —
для показа и для поиска по имени. Поверхность из D2 обрабатывает
`CSURF_EXT_MIDI_DEVICE_REMAP`: старый номер совпал с нашим — берётся новый,
настройки сохраняются. Вход ищется по имени (`findMidiInput`) при загрузке
расширения — требование «находиться по имени после перезапуска», — а также
при смене входа, показе настроек и по Refresh, где строке состояния нужно
знать, есть ли устройство (D7). Если вход найден под другим номером, номер в
настройках заменяется найденным и настройки сохраняются: по нему
`CSURF_EXT_MIDI_DEVICE_REMAP` узнаёт выбранный вход. Поиск раз в секунду
(`kMidiLookupInterval`) убирается.

Отвергнуто:
- поиск раз в секунду — опрос конфигурации;
- поиск при каждом запуске транспорта — лишняя работа: номер меняется только
  со сменой набора устройств.

### D7. Строка состояния без проверок на кадре

Разведка — `findings.md`, R4 и R7.

Имя канала (`GetInputChannelName`), включён ли вход MIDI (маска `midiins`) и
есть ли устройство (`GetMIDIInputName`) читаются при загрузке, показе и смене
настроек, по Refresh и по `CSURF_EXT_MIDI_DEVICE_REMAP`. Есть ли канал звуковой
карты — из признака хука (D3). Кадр строку только рисует.

## Risks / Trade-offs

- [Конец count-in не сообщается] → момент сдвига позиции кадр считает по
  разнице позиций и скорости (D5).
- [Отключение устройства MIDI без события] → строка состояния сообщает о нём
  при показе настроек и по Refresh (дельта `timing-display`).
- [Главный поток занят, кадров нет] → данные ждут в очереди атак и в истории
  MIDI-входа (46 568 событий) и встают в строки на первом кадре.
- [REAPER закрывает карту, когда окно REAPER не активно] → калибровка
  обрывается с названием настройки (D4).
