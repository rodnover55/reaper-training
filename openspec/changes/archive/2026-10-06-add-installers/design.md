# Design

## Context

Мотивация — `proposal.md`, раздел Why; требования — дельта `platform-support`
в `specs/`.

Что есть сейчас:

- CI собирает пресетом `release` три голых модуля — `reaper_training.so`,
  `.dll`, `.dylib` — и выкладывает их по тегу в Releases вместе с
  `SHA256SUMS.txt`. Сборка Linux идёт в контейнере `ubuntu:22.04`.
- `cmake --install` кладёт модуль разработчику в папку ресурсов REAPER по
  умолчанию: `%APPDATA%\REAPER`, `~/Library/Application Support/REAPER`,
  `~/.config/REAPER`.

Что известно о REAPER 7.82 (разобраны его установщики для трёх систем):

- **Windows.** Установщик REAPER — NSIS, 32-битный даже для x64-версии.
  Папку программы он, по описаниям, пишет в значение по умолчанию ключа
  `HKLM\SOFTWARE\REAPER`; в какое представление реестра (64 или 32 бита) —
  не проверено. Портативная установка в реестр не пишет. У `reaper.exe` есть
  версия файла (7.8.2.0), машина в заголовке PE — `0x8664`. Класс главного
  окна — `REAPERwnd` (строка есть в `reaper.exe`).
- **macOS.** `REAPER.app` из образа DMG перетаскивается в «Программы».
  Идентификатор — `com.cockos.reaper`, версия в `CFBundleShortVersionString`
  — `7.82.0_3385784u`.
- **Linux.** Архив с `install-reaper.sh`: программа ставится в `/opt/REAPER`,
  `~/opt/REAPER` или папку по выбору; по желанию — ярлык
  `cockos-reaper.desktop` с `Exec="<папка>/reaper" %F` и ссылка
  `/usr/local/bin/reaper`. Папку ресурсов сценарий выбирает так:
  `reaper.ini` рядом с программой — портативная, иначе `~/.config/REAPER`,
  иначе старая `~/.REAPER`, если в ней есть `reaper.ini`. Первая строка
  `whatsnew.txt` рядом с программой — `v7.82 - October 4 2026`.
- **Flatpak** (`fm.reaper.Reaper` на Flathub, среда `org.freedesktop.Platform`
  25.08 — glibc новее 2.35): настройки — в
  `~/.var/app/fm.reaper.Reaper/config/REAPER`.

SWS — самое известное расширение REAPER — на Windows ставится установщиком
NSIS без прав администратора в папку ресурсов (проверяет в ней `reaper.ini`),
на macOS раздаётся образом DMG, на Linux — архивом.

## Goals / Non-Goals

**Goals:**

- Установщик на каждой системе — родной для неё инструмент, который
  пользователь узнаёт: мастер установки на Windows, пакет `.pkg` на macOS,
  сценарий оболочки на Linux, как у самого REAPER.
- Установщик собирается у разработчика той же командой, что в CI.

**Non-Goals:**

- Общий для трёх систем исходник установщика: логика поиска REAPER у каждой
  системы своя, и общий слой её не сократит.
- Автообновление расширения.

## Decisions

### D1. Родной инструмент на каждую систему, без CPack

Установщики описаны исходниками своих инструментов в `installer/<система>/`,
CMake только вызывает инструмент (D5).

Отвергнуто:

- CPack. У генератора Inno Setup шаблон кладёт деинсталлятор в папку
  установки, то есть в папку ресурсов REAPER, а проверку REAPER пришлось бы
  дописывать в чужой шаблон. Генератор productbuild не умеет проверку
  установки на JavaScript без своего шаблона. Для Linux подходящего
  генератора нет: STGZ спрашивает про лицензию и префикс и ничего не ищет.
- Кроссплатформенные конструкторы (InstallBuilder, install4j — платные;
  Qt Installer Framework — тянет Qt и рассчитан на установку в Program Files
  и `/Applications`).

### D2. Windows — Inno Setup

Сценарий `installer/windows/reaper-training.iss`:

- `PrivilegesRequired=lowest`, без возможности повысить права: установка
  всегда в режиме пользователя, окна UAC нет. Запись об удалении — в
  `HKCU`, «Установка и удаление программ» её показывает.
- `ArchitecturesAllowed=x64compatible`: Windows x64 и Windows на ARM, где
  REAPER для ARM64EC загружает модули x64.
- `{app}` — папка ресурсов REAPER, модуль — в `{app}\UserPlugins`.
  `UsePreviousAppDir=no`: папка ищется заново при каждом запуске, а не
  берётся из прошлой установки. Деинсталлятор — в
  `{userpf}\reaper-training` (`%LOCALAPPDATA%\Programs`), а не в папке
  REAPER. Один `AppId` на все версии: новая версия обновляет ту же запись, а
  журнал удаления дописывается — удаление убирает модуль из всех папок, куда
  он ставился.
- Поиск REAPER в `[Code]` при запуске:
  1. папка программы из `SOFTWARE\REAPER` в `HKLM` и `HKCU`, в 64- и
     32-битном представлении реестра, и обычные папки
     `Program Files\REAPER (x64)` и `Program Files\REAPER`;
  2. подходит папка с `reaper.exe`, у которого машина в заголовке PE —
     `0x8664` (x64) или `0xAA64` (ARM64X) и версия файла — 7 и выше;
     неизвестная версия считается подходящей;
  3. `reaper.ini` рядом с `reaper.exe` — папка ресурсов эта же, иначе
     `%APPDATA%\REAPER`;
  4. программы нет, но есть `%APPDATA%\REAPER\reaper.ini` — ставится туда.
- REAPER не найден — вопрос «указать папку портативного REAPER?». «Нет» —
  выход, «Да» — страница выбора папки; папка принимается, если в ней есть
  `reaper.ini`, а `reaper.exe` в ней, если есть, проходит те же проверки.
  Найден, но не подходит (32 бита, версия ниже 7), — сообщение с причиной и
  тот же вопрос. В тихом режиме (`/VERYSILENT`) вопросы получают ответ
  «нет»; папку можно задать ключом `/DIR=`, и она проверяется так же.
- Запущенный REAPER — окно класса `REAPERwnd` — перед установкой и перед
  удалением: сообщение «закройте REAPER» с кнопками «Повтор» и «Отмена».
  `CloseApplications=no`: менеджер перезапуска Windows видит только REAPER,
  который держит старый модуль, и при первой установке молчал бы.
- Языки — английский и русский, по языку Windows.

Отвергнуто:

- NSIS (им ставятся REAPER и SWS) — проверку процесса и выбор языка пришлось
  бы собирать из плагинов, сценарий длиннее; в раннерах его нет.
- WiX и MSI — установка для одного пользователя в MSI держится на
  `ALLUSERS=2` и `MSIINSTALLPERUSER`, поиск REAPER — на пользовательских
  действиях на C++ или C#; несоразмерно одному файлу.
- MSIX — запись в `%APPDATA%` перенаправляется в контейнер пакета, REAPER
  файла не увидит.

### D3. macOS — пакет .pkg с установкой в домашнюю папку

`pkgbuild` собирает компонентный пакет с модулем и путём установки
`/Library/Application Support/REAPER/UserPlugins`; `productbuild` оборачивает
его описанием `installer/macos/distribution.xml`:

- `<domains enable_anywhere="false" enable_currentUserHome="true"
  enable_localSystem="false"/>` и `pkg-ref` без `auth`: установка идёт от
  имени пользователя без пароля, путь пакета отсчитывается от домашней папки
  — модуль попадает в `~/Library/Application Support/REAPER/UserPlugins`.
- `<installation-check>` на JavaScript Installer: ищет `REAPER.app` с
  идентификатором `com.cockos.reaper` в `/Applications` и `~/Applications`,
  берёт старшую цифру `CFBundleShortVersionString`; без приложения
  принимает `reaper.ini` в папке ресурсов. Отказ — `my.result.type =
  'Fatal'` с объяснением. Внешние программы проверка не запускает: иначе
  Installer показал бы ещё одно предупреждение.
- `<must-close>` с `com.cockos.reaper`: Installer сам просит закрыть REAPER.
- `<allowed-os-versions>` от 12.0; `hostArchitectures="arm64,x86_64"` —
  иначе на Apple Silicon Installer предлагает поставить Rosetta.
- Тексты — `en.lproj` и `ru.lproj` в ресурсах пакета.

Installer не ставит на файлы из пакета атрибут карантина, поэтому шаг с
`xattr` уходит. Сам пакет не подписан: macOS 12–14 открывает его через
«Открыть» в контекстном меню, macOS 15 и новее — через «Всё равно открыть»
в «Конфиденциальность и безопасность».

Отвергнуто:

- Образ DMG с перетаскиванием — в скрытую `~/Library` не перетащить, а
  модуль из образа несёт карантин.
- Приложение-установщик (AppleScript или Swift) — так же не подписано, к нему
  добавляется App Translocation, а скопированный им модуль наследует
  карантин.
- Пакет с установкой в систему и сценарием `postinstall`, который копирует
  модуль в домашнюю папку, — сценарий идёт от root, нужен пароль
  администратора.

### D4. Linux — самораспаковывающийся .run (makeself) со сценарием на sh

makeself собирает из `installer/linux/install.sh` и модуля файл `.run`:
сценарий оболочки с архивом и контрольной суммой SHA-256. Для запуска нужны
только `sh`, `tar` и `gzip`. Запуск — `sh reaper-training-…-linux-x86_64.run`,
ключи сценарию — после `--`: `--uninstall`, `--resource-path <папка>`.

`install.sh`, POSIX sh:

- От root (`id -u` = 0) — отказ.
- Ищет программу REAPER: `reaper` в `PATH`, `/opt/REAPER/reaper`,
  `~/opt/REAPER/reaper`, `Exec` из `cockos-reaper.desktop` в
  `~/.local/share/applications`, `/usr/local/share/applications`,
  `/usr/share/applications`. Ссылки раскрываются `readlink -f`.
- Для каждой программы: машина в заголовке ELF — x86-64, иначе пропуск с
  сообщением; версия — из первой строки `whatsnew.txt` рядом, ниже 7 —
  пропуск; папка ресурсов — по правилу `install-reaper.sh` (Context).
- Flatpak: `flatpak info fm.reaper.Reaper` — папка
  `~/.var/app/fm.reaper.Reaper/config/REAPER`, версия — из вывода
  `flatpak info`.
- Программ нет, но есть `~/.config/REAPER/reaper.ini` — ставит туда.
- Ставит во все найденные папки ресурсов без повторов: обычный REAPER и
  Flatpak живут рядом и не видят расширения друг друга.
- Замена атомарная: копия во временный файл в той же `UserPlugins` и
  `mv`. Запущенный REAPER держит старый файл открытым и работает дальше;
  запись поверх загруженного `.so` его бы уронила. Запущенный REAPER виден по
  `/proc/*/comm` — тогда сообщение «перезапустите REAPER».
- Сообщения на русском, если язык из `LC_ALL`, `LC_MESSAGES` или `LANG`
  начинается с `ru`, иначе на английском.

Отвергнуто:

- Пакеты deb и rpm — ставятся только от root, пишут только в системные
  папки и у каждого дистрибутива свои.
- Расширение Flatpak — работает только для REAPER из Flatpak и требует
  публикации на Flathub.
- Архив `tar.gz` со сценарием — на шаг больше: распаковать, потом запустить.

### D5. Цель CMake `installer`

`installer/CMakeLists.txt` подключается из корневого и заводит цель
`installer` для текущей системы: `iscc`, `pkgbuild` и `productbuild` или
`makeself` ищутся `find_program` (для Inno Setup — и в его обычных папках
версий 6 и 7). Инструмента нет — цель есть, но при сборке падает с
сообщением, какой инструмент поставить: так отсутствие инструмента в CI не
проходит молча. Цель не входит в `all`: обычная сборка не требует
инструментов установщика.

Версия — `PROJECT_VERSION`. Результат — `<каталог сборки>/installer/`:

- `reaper-training-<версия>-windows-x64-setup.exe`
- `reaper-training-<версия>-macos.pkg`
- `reaper-training-<версия>-linux-x86_64.run`

Пресет сборки `installer` — на конфигурации `release`. У разработчика:
`cmake --workflow --preset release && cmake --build --preset installer`.

### D7. Документация

`docs/install.md`: установка установщиком для каждой системы, включая
подтверждение неподписанного установщика (SmartScreen на Windows, Gatekeeper
на macOS) и выбор «Установить только для меня» на macOS; обновление и
удаление; ручная установка файлом — отдельным разделом для портативного
REAPER и тех, кто не хочет установщик. `README.md` — команды и состав
релиза. `.github/release-notes.md` — таблица установщиков.

## Risks / Trade-offs

- [Установщики не подписаны: SmartScreen на Windows и Gatekeeper на macOS
  предупреждают при первом запуске] → в руководстве — как подтвердить
  запуск. Подпись — отдельное изменение, когда появятся сертификаты.
- [Installer на macOS иногда не выбирает сам «Установить только для меня» и
  просит пароль или выбор места — известная ошибка Installer.app] → в
  руководстве: нажать строку «Установить только для меня»; запасной путь —
  `installer -pkg … -target CurrentUserHomeDirectory` в Терминале.
- [Ключ реестра REAPER известен по описаниям, а не по документации] → поиск
  читает все четыре представления и обычные папки.
- [REAPER на Linux в своей папке без ярлыка и без `PATH` не найден] → если он
  запускался, его `~/.config/REAPER/reaper.ini` находится; портативный
  передаётся `--resource-path`.
- [Inno Setup бесплатен только для некоммерческого использования] → проект
  некоммерческий; при смене статуса — лицензия или NSIS.

## Migration Plan

Ручная установка ставит модуль туда же, куда установщик, поэтому установщик
просто заменяет файл. На macOS файл, поставленный вручную с пометкой
карантина, заменяется файлом без неё. На Windows расширение, поставленное
вручную, появляется в списке программ после первого запуска установщика.
Откат — удалить файл или поставить прошлую версию из Releases.
