# Tasks

Разведка (раздел 1) идёт до библиотек, модуля и окна. Её ответы записываются в
`findings.md` этого изменения и правят design и specs. Если сработало
стоп-условие из `proposal.md`, работа по разделам 2–5 не начинается, а решение
выносится пользователю.

## 1. Разведка MIDI-входа (R5)

- [ ] 1.1 Подготовить MIDI-источник на машине с REAPER: MIDI-инструмент
      пользователя или на Linux виртуальный порт `snd-virmidi` и скрипт,
      который шлёт Note On с заданным шагом (design D7). Проверка — REAPER
      видит устройство в Preferences → MIDI Devices, дорожка с этим входом
      пишет ноты с заданным шагом
- [ ] 1.2 В отладочной сборке взять `GetMidiInput` через `GetFunc` и писать в
      журнал события `GetReadBuf()` всех MIDI-входов в хуке до и после
      обработки: позицию и длину блока, сырое `frame_offset`, байты; при
      загрузке — есть ли функция. Проверка — Note On источника видны в
      журнале; в `findings.md` ответы R5.1 (функция, устройства с включённым,
      выключенным вводом и вводом только для управления) и R5.2 (вызов хука,
      блок событий, единицы смещения, разложены ли смещения в блоке)
- [ ] 1.3 Сделать отладочный сбор Note On выбранного MIDI-входа с позицией
      блока и сырым смещением, `TrainingDebug_SetMidiInput` и сверку с
      выделенным MIDI-айтемом (design D7): ноты айтема через `MIDI_GetNote` и
      `MIDI_GetProjTimeFromPPQPos`, объединение по 40 мс, ноты на лету по
      `P + o / sr`. Проверка — на записанном MIDI-айтеме действие печатает в
      консоль сдвиг «на лету − айтем», остаток, число нот без пары, задержки и
      поправки REAPER и длину блока
- [ ] 1.4 R5.3: записать дубли с MIDI-источника при буфере 128, 512 и 1024,
      Input и Output manual offset 0 и 480 сэмплов, галке «Use audio driver
      reported latency» включённой и выключенной, скорости проекта 1.0 и 0.8;
      квантование ввода выключено. Проверка — в `findings.md` таблица по
      дублям; правило времени Note On восстановлено: сдвиг постоянен в
      пределах тика айтема и объясняется задержками, поправками и длиной
      блока. Не сошлось — R5.5 через `MIDI_GetRecentInputEvent`; не сошлось и
      там — стоп-условие, решение пользователю
- [ ] 1.5 R5.4: по журналу выяснить, что происходит с Note On при count-in,
      запуске, переходе петли, паузе и продолжении. Проверка — в
      `findings.md` поведение по каждому случаю; правила стоящей позиции из
      `add-timing-trainer` (R4) подтверждены для MIDI или исправлены
- [ ] 1.6 Внести итоги разведки в design (D1, D2, D4, D5) и specs. Проверка —
      `openspec validate add-midi-input --strict` проходит, изменения показаны
      пользователю

## 2. Note On и компенсация в библиотеках

- [ ] 2.1 Сделать в `training_onset` распознавание Note On, объединение Note
      On одного удара по `deadTimeMs` и перевод смещения MIDI в дробные
      сэмплы в единицах из R5.2 (design D4). Проверка — тесты: аккорд из трёх
      Note On за 15 мс даёт одну ноту в первом; Note On через 39.9 мс
      объединяется, через 40 и 60 мс — нет; скорость 0, Note Off, CC и pitch
      bend нот не дают; каналы 1, 10 и 16 дают; одни и те же события, разбитые
      по блокам по-разному, дают одно и то же; сброс начинает объединение
      заново; проверка изоляции библиотеки проходит
- [ ] 2.2 Сделать в `training_grid` компенсацию MIDI по правилу R5.3 (design
      D2). Проверка — тесты: каждая строка таблицы R5.3 из `findings.md` даёт
      свой сдвиг; при скорости 0.8 время Note On считается по
      `P + (o / sr − компенсация) × r`

## 3. MIDI-вход в модуле

- [ ] 3.1 Научить `AudioInput` MIDI-входу (design D1, D3): вид входа и номер
      устройства от главного потока; хук копирует короткие сообщения в очередь
      событий, флаг «транспорт идёт» в заголовке отдельно от числа данных,
      флаг «устройство не открыто»; рабочий поток — Note On и объединение,
      стоящая позиция, запуски, вид входа в `HookOnset`; смена входа
      сбрасывает объединение и детектор, но не начинает запуск. Проверка — 10
      минут воспроизведения с Note On каждые 125 мс с виртуального порта: в
      журнале все Note On, потерь в очередях нет, пустые блоки не начинают
      новый запуск; Note On во время count-in и первых блоков после запуска
      отброшены
- [ ] 3.2 Сделать в `Trainer` компенсацию для обоих видов входа при запуске и
      выбор её по виду ноты, поиск номера MIDI-устройства по имени на каждом
      тике и состояния «выбранного входа нет» и «ввод не включён в REAPER»
      (design D2, D5). Проверка — сценарии `hit-timing` «MIDI-вход вместо
      канала», «Ни одна дорожка не стоит на запись» для MIDI, «Ранняя нота на
      MIDI-входе», «Count-in на MIDI-входе», «Отпускание клавиши», «Педаль и
      колесо», «Канал 10», «Аккорд», «Бочка и хэт вместе», «Две ноты через
      60 мс»; смена входа посреди запуска не чистит список, и ноты до и после
      смены ложатся верно
- [ ] 3.3 Хранить вход в `ExtState`: ключ `midi_input` с именем устройства без
      псевдонима, `channel` — последний канал звуковой карты (design D5).
      Проверка — сценарии `timing-display` «Перезапуск REAPER», «MIDI-устройство
      сменило номер» и «Настройки прошлой версии»: `reaper-extstate.ini`
      версии 0.1.0 с `channel=2` даёт канал 2
