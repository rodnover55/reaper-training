# Tasks

Разведка (раздел 1) идёт до библиотек, модуля и окна, тем же методом, что
разведка R2 правила записи звука в `add-timing-trainer`. Её ответы
записываются в `findings.md` этого изменения и правят design и specs. Если
сработало стоп-условие из `proposal.md`, работа по разделам 2–5 не начинается,
а решение выносится пользователю.

## 1. Разведка MIDI-входа (R5)

- [ ] 1.1 Подготовить MIDI-источник на машине с REAPER: MIDI-инструмент
      пользователя или на Linux виртуальный порт `snd-virmidi` и скрипт,
      который шлёт заданную последовательность событий, в том числе плотную
      неповторяющуюся: промежутки от 2 до 200 мс, разные ноты и скорости, Note
      On, Note Off и CC вперемешку (design D7, D8). Для проверки нумерации —
      второе MIDI-устройство (второй виртуальный порт). Проверка — REAPER видит
      устройства в Preferences → MIDI Devices, дорожка с этим входом пишет
      последовательность без потерь
- [ ] 1.2 В отладочной сборке взять `GetMidiInput` через `GetFunc` и писать в
      журнал сырые события `GetReadBuf()` всех MIDI-входов в хуке до и после
      обработки: позицию и длину блока, сырое `frame_offset`, байты; при
      загрузке — есть ли функция. Проверка — события источника видны в
      журнале; в `findings.md` ответы R5.2 (вызов хука, блок событий, единицы
      смещения, разложены ли смещения в блоке) и первая часть R5.1 (функция,
      устройства с включённым, выключенным вводом и вводом только для
      управления)
- [ ] 1.3 R5.1, нумерация — так же, как R1 проверила каналы: номер устройства
      в `GetMidiInput`, `GetMIDIInputName` и `I_RECINPUT` дорожки один и тот
      же; номер держится за устройством, когда подключено второе устройство,
      когда устройства подключены в другом порядке и после перезапуска REAPER;
      что отдают `GetNumMIDIInputs` и `GetMIDIInputName` для отключённого
      запомненного устройства; какие MIDI-входы, в каком порядке и с какими
      подписями REAPER показывает в меню входа дорожки — с включённым вводом,
      выключенным, только для управления, отключённые запомненные, с
      псевдонимом — и как кнопка входа дорожки показывает вход, когда
      устройства нет. Проверка — в `findings.md` таблица номеров по каждому
      случаю рядом с входом дорожки и снимки меню входа дорожки; если номер не
      держится — это записано, и решение о хранении входа (design D5) вынесено
      пользователю
- [ ] 1.4 Сделать инструменты R5.3 по образцу R2 (design D7, D8): запись
      сырых событий выбранного MIDI-входа за запуск с позициями блоков и
      смещениями, `TrainingDebug_SetMidiInput` и сверку сырых событий с
      выделенным MIDI-айтемом — отрезки событий айтема (`MIDI_GetAllEvts`,
      `MIDI_GetProjTimeFromPPQPos`) на 20, 50 и 80 % его длины ищутся среди
      сырых событий по совпадению байтов, на лету — `P + o / sr` без
      компенсации. Проверка — на записанном дубле действие печатает для
      каждого отрезка место, сдвиг «на лету − айтем», остаток пар, задержки и
      поправки REAPER, длину блока и тик айтема
- [ ] 1.5 R5.3: найти в бинарнике REAPER и `reaper.ini` настройки, которые
      касаются времени записи MIDI, как R2 перебрала `adjrec*`; записать дубли
      плотной последовательности с квантованием ввода выключенным, строками
      таблицы R2 — буфер 512, скорость 1.0, `adjreclat` 1, поправки 0 / 0;
      поправка входа 480; поправка выхода 480; `adjreclat` 0 с поправками
      0 / 0 и 480 / 0; `adjreclat` 2 и 4; скорость 0.8; буфер 128 и 1024 — и
      строками для каждой найденной настройки MIDI; проверить, действует ли

      айтема при скорости 0.8. Проверка — в `findings.md` таблица с колонками

      Не сошлось — R5.5 через `MIDI_GetRecentInputEvent` тем же методом; не

- [ ] 1.7 R5.4: по журналу выяснить, что происходит с Note On при count-in,

## 2. Note On и компенсация в библиотеках

- [ ] 2.1 Сделать в `training_onset` распознавание Note On, объединение Note
      On одного удара по `deadTimeMs` и перевод смещения MIDI в дробные
      сэмплы в единицах из R5.2 (design D4). Проверка — тесты: аккорд из трёх
      Note On за 15 мс даёт одну ноту в первом; Note On через 39.9 мс
      объединяется, через 40 и 60 мс — нет; скорость 0, Note Off, CC и pitch
      bend нот не дают; каналы 1, 10 и 16 дают; одни и те же события, разбитые
      по блокам по-разному, дают одно и то же; сброс начинает объединение
      заново; проверка изоляции библиотеки проходит
- [ ] 2.2 Сделать в `training_grid` компенсацию MIDI по формуле R5.3 (design
      D2). Проверка — тесты: каждая строка таблицы R5.3 из `findings.md` даёт
      свой сдвиг; при скорости 0.8 время Note On считается по
      `P + (o / sr − компенсация) × r`
