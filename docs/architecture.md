# Ограничения архитектуры

Обязательные правила: где лежит код и какие слои какие используют. 
Нарушения этих правил равны критическим ошибкам в коде

## `libs/core` — ядро

Новое ядро. То, что до него называлось ядром, — старое ядро.

Ядро не использует ни другие слои, ни REAPER: связей с ними в нём нет.
Остальные слои могут использовать ядро, ядро их — нет. Правило жёсткое.

Ядро использует только время ядра: `training::core::Moment` и
`training::core::Interval`. Любое другое время — часы ОС, позиции
REAPER — в ядре запрещено: связка переводит его во время ядра до вызова ядра.

## `libs/render`

`libs/render` использует только ядро. Связей с REAPER у него нет.

`libs/render` — модуль отрисовки. Он содержит интерфейс отрисовки примитивов
и независимую логику отрисовки компонентов плагина: компоненты рисуются через
этот интерфейс. Прямых вызовов функций отрисовки REAPER в нём нет.

## `libs/reaper`

`libs/reaper` — всё, что принимает данные от REAPER и преобразует их в
сущности ядра, и реализация интерфейса отрисовки примитивов из
`libs/render` для REAPER.

`libs/reaper` может использовать любые слои, кроме `src`.

## `src`

`src` — только точка инициализации: точка входа в DLL, которую вызывает
REAPER. `src` может использовать любые слои.
